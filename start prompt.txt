## Utmaningen
Ericsson lagrar enorma mängder videoinspelningar (möten, kurser, skärminspelningar, ofta flera timmar och hundratals MB–GB) och presentationer/PDF:er på SharePoint, OneDrive och Ericsson Play. Lagringen tar slut, så värdefull information raderas, och dokument dupliceras när folk laddar ner och laddar upp dem igen. Vi ska bygga ett verktyg som frigör lagring utan att förlora information:
1. Lagringsminskning: ersätt video med text + nyckelbilder (slides) och hitta dubbletter.
2. Dataaktivering: gör innehållet sökbart och AI-redo (t.ex. för RAG och träning av interna modeller).
Extra: när en anställd slutar ska deras filer analyseras mot befintliga kopior och raderas bara om en dubblett redan finns.
Ericssons referensscenario: en 2-timmarsinspelning (~1 GB) blir ~50 KB text + ~2 MB slidebilder, ca 99 % reduktion. Lösningen ska kunna fungera utan känslig data, och delösningar räcker som start.

## Vår idé
En lokal pipeline som gör om en inspelning eller ett dokument till ett litet, sökbart "kunskapspaket" (text, nyckelbilder, metadata, hashar), plus ett register som hittar dubbletter och revisioner över filer.

Delar:
1. Video → paket: ljud → transkription med talare och tidsstämplar; nyckelbilder/slides via scene detection; OCR på slides.
2. Tidslänkning: varje textsegment kopplas till rätt bild, så "som ni ser här" fortfarande går att förstå.
3. Dokument → slides: PDF/PPTX delas upp i slides, varje slide får hash (exakt text-hash + perceptuell hash på renderad bild); hitta dubbletter ("(1).pdf"), delade slides mellan presentationer och revisioner med små ändringar.
4. Sök: en fråga returnerar matchande bild + text vid rätt tidpunkt.
5. Offboarding: jämför en avgående persons filer mot registret; markera bara filer som redan finns på annat håll som säkra att radera.
Bonus: länka videons nyckelbilder till slide-registret ("single source of truth"), AI-redo export (JSONL/Markdown), undersöka om inspelningen kan återskapas från paketet.

## Teknikstack (Python 3.11/3.12, allt körs lokalt)
- Video: ffmpeg, faster-whisper, pyannote.audio eller whisperX (talare), opencv, imagehash, Tesseract eller PaddleOCR
- Dokument: PyMuPDF, python-pptx, LibreOffice (PPTX→PDF), hashlib (SHA-256), imagehash
- Lagring/sök: SQLite + FTS5, ev. sentence-transformers för semantisk sök
- UI/API: Streamlit (demo) och/eller FastAPI
- Test: pytest

## Datakontrakt (ändras bara efter att alla sagt ok)
Recording-paket (JSON):
```json
{
  "id": "rec_001",
  "source": {"file": "meeting.mp4", "sha256": "...", "duration_s": 7200, "size_bytes": 1073741824},
  "segments": [
    {"start": 12.4, "end": 18.9, "speaker": "SPEAKER_01", "text": "...", "frame_id": "f_003"}
  ],
  "frames": [
    {"id": "f_003", "t": 10.0, "file": "frames/f_003.webp", "phash": "...", "ocr_text": "...",
     "slide_ref": {"doc_id": "...", "slide_no": 4, "slide_hash": "..."}}
  ]
}
```
Dokument/slide-register: per fil (sha256, filnamn, storlek, metadata som dokumentnummer, revision, författare, datum) och per slide (doc_id, slide_no, text_hash, phash, text). Använd SQLite.
